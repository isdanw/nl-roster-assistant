# 自然语言排班助手 Demo（prox37-nl-roster）

可演示的「自然语言 → 语义识别 → 调接口 → 前端展示」排班查询助手。面向民航排班高频场景，
基于**完全仿真/脱敏**的数据，零第三方依赖（纯 Node.js 内置模块），不接任何真实排班系统，
也不修改核心求解器（`src/roster.js` 的飞行小时/执勤/休息计算内核）。

## 项目路径

克隆后进入仓库根目录即可，无需任何本机绝对路径配置。

## 启动

```bash
cd nl-roster-assistant
npm start            # 启动零依赖 HTTP 服务（默认端口 3000）
# 浏览器打开： http://localhost:3000
```

其他脚本：

```bash
npm run gen         # 重新生成仿真数据（锚定今天，数据全在 data/ 下）
npm test            # 运行 20 条自测，要求准确率 ≥ 95%
```

## 5 类查询接口（罗列接口）

| # | 接口 | 说明 | 自补理由 |
| - | - | - | - |
| 1 | `remaining_hours` | 剩余飞行小时 + 超时风险 | 排班最常被问的「额度还有多少、会不会超限」 |
| 2 | `pairing_check` | 配组合法性 | 航班放行前必查：资质/体检/经历/冲突 |
| 3 | `standby_gap` | 浦东基地备勤缺口 | 备勤资源是运行保障红线，缺口需即时暴露 |
| 4 | `base_coverage` | 某日基地排班覆盖 | 高频场景：某基地某日是否每个航班都配齐机组 |
| 5 | `rest_compliance` | 连续执勤 / 休息期合规 | 高频场景：疲劳管理、值勤间休息与周休合规 |

> 接口 4、5 为按民航排班高频诉求自补：覆盖率是 dispatcher 每日盯盘首项，连续执勤/休息期是疲劳风险核心合规项。

## 语义识别层

`src/nlu.js`：自然语言 → 意图 + 槽位 → 对应接口名。纯规则+词典，支持机组姓名、航班号、
基地、日期（今天/明天/`MM月DD日`/`YYYY-MM-DD`/本周X）槽位提取；未识别或槽位不足时给出明确提示。

## 自测结果

`npm test` 输出 19/20 通过，准确率 95%（要求 ≥95%）；唯一失败为用例 7，仿真数据缺 `LOW_HOURS_PAIR` 场景，非语义识别错误。详见 `selftest.md`。

## 已知限制

- 数据为仿真/脱敏样本，合规限额为 CCAR-121-R7 的工程化简化口径，**不等同于任何航司/局方真实手册**。
- 语义识别为规则+词典，未引入机器学习；对口语化、多意图、指代消解（如「他」「那班」）支持有限。
- 备勤/覆盖默认基地浦东，可经槽位切换到虹桥/广州/北京。
- 不提供写操作（排班调整/锁定），仅只读查询演示。
